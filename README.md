# When Do Surrogate Metrics Work? A Finite-Sample Comparison Under Realistic Failure Modes

Replication code for the paper by Zihao Chen (University of Washington).

Paper: [arXiv:2609.30528](https://arxiv.org/abs/2609.30528).

The package contains the estimators, the data-generating processes, the
simulation engine, the scripts that run every simulation and real-data analysis
reported in the paper, and the resulting tables as CSV files in
`results/tables/`.

## Requirements

Python 3.8 (the results were produced with CPython 3.8.13 on macOS, Apple
silicon, 8 cores) and these exact package versions:

| Package | Version |
|---|---|
| numpy | 1.21.5 |
| scipy | 1.9.3 |
| pandas | 1.5.3 |
| scikit-learn | 1.1.3 |
| matplotlib | 3.5.1 |
| scikit-uplift | 0.5.1 |
| pyarrow | 17.0.0 |

```bash
pip install -r requirements.txt
# or
conda env create -f environment.yml && conda activate surrogate-metrics
```

The prediction models are fit with scikit-learn, so a different version can
move the last digits of the estimates even with identical seeds.

## Data

- **Hillstrom** (MineThatData e-mail experiment): downloaded automatically by
  scikit-uplift (`sklift.datasets.fetch_hillstrom`) on first use.
- **LaLonde** (NSW, Dehejia and Wahba sample): read at run time from the NBER
  mirror, `https://users.nber.org/~rdehejia/data/nsw_dw.dta`.
- **Criteo uplift v2.1**: download `criteo-uplift-v2.1.csv` from
  <https://ailab.criteo.com/criteo-uplift-prediction-dataset/> (3,248,115,221
  bytes, 13,979,592 rows plus a header, SHA-256
  `e4d7c710ca1f38e523309d0f8a0745d1b53e7392d51f20d1088b6cfeaef222ef`) and set
  `export CRITEO_CSV=/path/to/criteo-uplift-v2.1.csv`. The Criteo scripts also
  accept `--data PATH`. The semi-synthetic and multi-surrogate analyses, and
  the multi-surrogate row of the joint-covariance check, use a covariate pool
  fitted on these data by `scripts/run_semisynthetic.py`.

## Reproducing the results

`reproduce.sh` runs every command below in dependency order (the full run
takes many hours; the Criteo steps run only when `CRITEO_CSV` is set). Run
each command from the repository root with `PYTHONHASHSEED=0`. Every script
writes to `results/tables/`; `scripts/export_eval_csv.py` and
`scripts/export_tables_csv.py` then write the CSV files shipped here from the
scripts' JSON and markdown output.

`results/tables/` holds summary tables only, one row per cell (design,
configuration, labeled fraction and method). Nine scripts also write
per-replication output (`dgp9_results.csv`, `dgp10_results.csv`,
`aipw_full_eval.csv`, `corrected_variance_verification.csv`,
`hybrid_eval.csv`, `switch_vs_hybrid.csv`, `hybrid_ci_validation.csv`,
`gbt_comparison.csv`, `surrogacy_test_misspec.csv`, and the `*_raw.csv`
files); these are not shipped and are regenerated by the listed command. The
shipped `<name>_summary.csv` holds the summary rows of those analyses. Run
times are wall-clock on the reference machine; "est." marks an estimate.

Figure A2 with `scripts/run_limit_experiment.py`).

## Seeds

The master seed is 42. Every replication's seed is derived from the master
seed and the cell and replication indices with SHA-256
(`derive_seed` in `src/simulations/simulation.py`), so results do not depend
on the number of worker processes or on Python's salted `hash()`. Set
`PYTHONHASHSEED=0` as `reproduce.sh` does.

## Layout

```
src/            estimators (src/methods), data-generating processes
                (src/dgps), simulation engine (src/simulations), evaluation
                metrics, real-data loaders, configuration and result-row I/O
run_*.py        simulation drivers
scripts/        focused simulations, calibration checks, real-data analyses,
                and the two CSV export scripts
results/tables/ the summary tables behind the paper, as CSV
reproduce.sh    every command, in order
```
